# מעלית שבת — מנחם בגין 17, גבעת שמואל

אתר ציבורי בעברית למעלית אחת, עם בחירת קומה ללא ברירת מחדל, תחזית הגעה,
תצוגה לטלפון/טאבלט/מחשב, זמני שבת וחג, פרשת שבוע, מזג אוויר ובקשת השארת מסך דולק.

**המערכת כוללת גלאי שמע חי, שרת נתונים וחיבור דרך קלאודפלייר. הגלאי והדיווח
פועלים אוטומטית עם הפעלת הרזברי. אימות הזיהוי בקומה 7 במסלול שבת עדיין נדרש.**
תחזיות הנסיעה בין הקומות עדיין מבוססות על זמנים משוערים; הדגמה יזומה מסומנת בנפרד.

- אתר: <https://udid.github.io/shabat_elevator/>
- מאגר: <https://github.com/udid/shabat_elevator>

## הרצה מקומית

סביבת הפיתוח באמצעות `uv` משתמשת ב־Python 3.13 ומעלה. לשרת ללא מיקרופון אין
תלויות חיצוניות; הגלאי דורש NumPy ו־sounddevice. הוראות נפרדות ל־Python 3.11
ברזברי מופיעות בהמשך.

```powershell
uv venv .venv
.\.venv\Scripts\python.exe run_metrics_server.py
```

פותחים <http://127.0.0.1:8000>. אפשר גם `python run_metrics_server.py` בכל מערכת עם Python מתאים.
פותחים את **הגדרות** (גלגל השיניים בכותרת) ולוחצים **הפעלת הדגמה**.
הכפתור זמין בכל זמן, גם במצב חיישן. בוחרים קומה כדי לראות את הספירה לאחור.
ההדגמה מסומנת במפורש ואינה שולחת מדידות לשרת. **סיום ההדגמה** מחזיר לתצוגה
הרגילה: נתוני החיישן או הסימולציה האוטומטית לפי הגדרות האתר ושעות הפעילות.
התפריט נסגר לאחר בחירה, בלחיצה מחוצה לו או ב־Escape.
בחירת הקומה הראשונה תמיד ריקה;
לאחר בחירה היא נשמרת במכשיר לפי מזהה הבניין. כדי להסיר אותה בוחרים שוב באפשרות הריקה.

## התנהגות שסוכמה

### אפיון תצוגה: כל הנתונים במבט אחד

העיצוב הנבחר הוא **גרפיט וענבר**: רקע `#1b1e23`, אזור תחזית `#252a31`,
טקסט שנהב והדגשות `#e5b76f`. גופן Heebo נטען מקומית מתוך `web/fonts/`,
לצד רישיון השימוש שלו. במחשב התחזית בצד ימין ומידע השבת ומזג האוויר לצדה;
בנייד המידע המשני מוצג מתחת לתחזית בפריסה קומפקטית.

המסך הראשי הוא לוח מידע קומפקטי: כל נתוני המעלית והשבת מופיעים יחד, ללא
גלילה בגדלי התצוגה שנבדקים בבדיקת הדפדפן. הפריסה מותאמת לרוחב ולגובה הזמינים.
גדלי הבדיקה (פיקסלי CSS): 320×640, 375×667, 390×844, 768×1024,
1366×768, 1280×600 ו־844×390 לרוחב. הבדיקות כוללות נתונים זמינים,
כשל בשירותי הלוח ומזג האוויר והדגמה יזומה.

- כותרת: שם האתר, חיווי חיבור לגלאי, מסך מלא ותפריט הגדרות. החיווי נשאר גלוי
  גם בהדגמה ובמצב בדיקה: ירוק כשמתקבלים דיווחים עדכניים, ענבר כשהשרת זמין אך
  הגלאי אינו מדווח, ואדום כשהאתר אינו מצליח להתחבר. חיבור אינו אישור לתחזית זמינה.
- הגדרות: הפעלת הדגמה ושמירת המסך דולק, שמבוקשת אוטומטית בכל טעינת האתר.
- שעון: לצד מצב המעלית. תאריך עברי ולועזי: בכרטיס השבת המאוחד.
- תחזית מרכזית: בחירת קומה, ספירה לאחור, התחנה הבאה או העצירה המשוערת וחץ כיוון.
  כאשר התחזית אינה זמינה מופיע הסבר אחד במקומה; מועד הפעילות הבא מופיע כשידוע.
- שורת מצב מיוחדת מופיעה בהדגמה או בבדיקה; חיווי החיבור הקבוע נמצא בכותרת.
- נתוני מדידה בשורה קצרה: זיהוי אחרון בקומה 7, משך המחזור ולצדו עדכון אחרון מהגלאי. זיהוי בהדגמה מסומן
  כמדומה; זיהוי או דיווח חיישן מיום קודם כוללים גם תאריך, כדי שלא ייראו עדכניים.
- מסלול בתפריט ההגדרות: שני הסבבים בשלמותם, סימון הקומה שנבחרה והעצירה הכפולה.
- כרטיס שבת מאוחד: תאריך היום, פרשה ותאריך הקריאה, שמות חגים כשישנם, כניסה
  ויציאה ותאריכיהן וחלון פעילות המעלית. המיקום מופיע פעם אחת באזור זה.
- כרטיס מזג אוויר: טמפרטורה, תיאור, טווח יומי ושעת עדכון.
- הסבר החישוב והמקורות נפתחים בחלון נפרד, הנסגר בכפתור או ב־Escape.

מלל חוזר, שעת הגעה המחושבת מהספירה לאחור והזמן שחלף מהזיהוי הוסרו מהמסך.
פרטי החישוב והכיול נשמרים בחלון ההסבר. ההתאמה אינה חותכת תוכן
כדי להעלים פס גלילה. במסך קטן מהטווח שנבדק או בהגדלת טקסט חריגה, תוכן נשאר
נגיש גם אם נדרשת גלילה. ההבחנה בין סימולציה, נתוני חיישן והערכה נשארת גלויה.
בחירת הקומה, מסלול הנסיעה וכללי חישוב התחזית והפעילות נשארים כמפורט להלן.

### מסלול ותחזית

- קומות: ‎-1, 0–12. קומה ‎-1 היא קומת חניון, ואינה קוד שגיאה או כיוון.
- מקור המדידה: Raspberry Pi עם מיקרופון בקומה 7, שמזהה את הצליל בעת **עזיבה**.
  התקנה במיקום הקבוע ואימות מול המעלית עדיין נדרשים לפני הסתמכות על הזיהוי.
- מיקום וכיוון מחושבים הם הערכות; אירוע החיישן מתייחס רק לקומה 7.
- מחזור הדגמה מלא: **570 שניות (09:30)**, מהגעה לקומה 7 עד ההגעה הבאה אליה.
- המסלול המעגלי, בדיוק בסדר שנמסר:

```text
0, 0, 12, 10, 8, 6, 4, 2, -1, 0, 11, 9, 7, 5, 3, 1, -1 → חזרה להתחלה
```

שתי הופעות 0 הרצופות בתחילת הרשימה הן עצירה אחת בעלת משך כפול.
הביקור האחר ב־0 נשמר לפי הרשימה כעצירה רגילה. אין נסיעה פיקטיבית בין שני אפסים.
בקומות שמופיעות יותר מפעם במחזור, מחושב הזמן לביקור הקרוב ביותר.

זמני הביניים הם **הנחות שטרם נמדדו בבניין**: יחס של 3 שניות לכל קומה בנסיעה
ו־12 שניות לכל יחידת עצירה. בהדגמה הכול מותאם יחסית ל־570 שניות; במצב חי
לאורך המחזור מהכיול או מהמדידה. מדידת המחזור המלא אינה מכיילת את זמני הביניים.
ההגדרות נמצאות ב־[web/config.json](web/config.json). אפשר לשנות את היחסים, המסלול,
`stopWeights` לפי קומה ואת משך המחזור. יש לכייל את מודל הנסיעה לפני שימוש בתחזית אמיתית.

## לוח פעילות

חלון הפעילות מתחיל **60 דקות לפני כניסת שבת או חג ומסתיים 60 דקות אחרי צאתם**.
אירועי חג/שבת רצופים מחוברים לחלון רציף. חול המועד לבדו אינו מפעיל מצב שבת.
הזמנים מחושבים ב־`Asia/Jerusalem`, לרבות שעון קיץ, עבור אזור גבעת שמואל
בקואורדינטות `32.078, 34.847`.

מקור הזמנים הוא Hebcal עם לוח ישראל: הדלקת נרות 18 דקות לפני השקיעה ויציאה לפי
צאת הכוכבים בשיטת 8.5 מעלות (`M=on`). `havdalahMinutes: null` בוחר שיטה זו;
מספר מפורש מחליף אותה בדקות לאחר השקיעה, לפי ההגדרה המקומית הרצויה.
אלו הגדרות לוח האתר; יש להתאים אותן גם לשעון הבקרה בפועל של המעלית.

אם לוח השנה אינו זמין ואין עותק תקף בזיכרון, האתר מסמן שחלון הפעילות אינו ידוע.
אפשר להפעיל הדגמה יזומה גם בימי חול. היא תמיד מסומנת ואינה משנה את לוח השבת.
מזג האוויר מתעדכן בנפרד; כשל בו אינו מפסיק את חישוב המעלית.

השארת המסך דולק משתמשת ב־Screen Wake Lock ב־HTTPS או localhost ומופעלת כברירת
מחדל בכל טעינה. אפשר לכבות ולהפעיל אותה מתפריט ההגדרות. נדרש אתר גלוי ודפדפן
תומך; מערכת ההפעלה יכולה לשחרר את הנעילה. האתר מציג את מצב הנעילה ומנסה לחדש
אותה בחזרה ללשונית, אם המשתמש לא כיבה אותה. סירוב או שחרור הנעילה כשהאתר גלוי
מוצגים למשתמש, והמתג חוזר למצב כבוי. בדפדפן שאינו תומך בכך המתג אינו זמין.
מצב מסך מלא זמין בנפרד.

## הקלטה וחיפוש פרמטרים לכיול

שני כלי שורת פקודה מיועדים לאיסוף שמע ולכיול מקומי. מתקינים את קבוצת תלויות השמע:

```powershell
uv sync --group audio
```

מציגים את התקני השמע ובוחרים את מספר המיקרופון מהרשימה:

```powershell
uv run --group audio python run_record_audio.py --list-devices
uv run --group audio python run_record_audio.py --device 1 --output data/recordings --duration-minutes 180
```

`--device 1` הוא דוגמה; משמיטים אותו כדי להשתמש בהתקן הקלט המוגדר כברירת מחדל.
ללא `--duration-minutes` ההקלטה ממשיכה עד `Ctrl+C`. ברירת המחדל תואמת לקבצים
הישנים: WAV, ערוץ אחד, PCM של 16 ביט, 44,100 דגימות בשנייה וקובץ בכל 300 שניות.
שם הקובץ הוא זמן הדגימה הראשונה במילישניות מאז Unix epoch, לדוגמה
`1791558000000.wav`. אפשר לשנות את אורך הקובץ באמצעות `--chunk-seconds`.
קליטת המיקרופון רציפה גם בזמן החלפת קבצים; הקובץ החלקי האחרון נסגר עם כותרת תקינה.
יומן `manifest.jsonl` מתעד את הקבצים ואת מצב ההקלטה. תקלה או אובדן שמע מדווחים
כשגיאה, וקובץ קיים אינו נדרס. אין הפעלת מיקרופון בעת הרצת הכיול.

מחפשים פרמטרים על ההקלטות החדשות או על תיקיית ההקלטות המקורית:

```powershell
uv run --group audio python run_calibrate_audio.py data/recordings --output data/calibration.json
uv run --group audio python run_calibrate_audio.py "C:\repos_old\projects\elevator\data" --output data/calibration-old.json
```

בכיול מוצלח (`ready`) נוצר גם **קובץ הגדרות מצומצם להרצה**, לצד הדוח המלא.
לדוגמה, עבור `data/calibration.json` ייווצר `data/calibration.runtime.json`.
אפשר לבחור את שמו בנפרד:

```powershell
uv run --group audio python run_calibrate_audio.py data/recordings --output data/calibration.json --runtime-output data/server-config.json
```

הקובץ המצומצם מכיל את סוג האירוע והקומה, `defaultCycleSeconds`, והגדרות
`detector`: ערוץ, גבולות תדר, סף SNR ועוצמת רעש ייחוס, סף עוצמת צלצול,
משכי אירוע, איחוד פעימות וזמן המתנה לחימוש מחדש. אין בו רשימות הקלטות,
אירועים היסטוריים, ציוני כיול או מערכים ספקטרליים.
אם `minimumEventBandDbfs` הוא `null`, לא נלמד סף עוצמה מוחלטת והסינון הזה
מושבת; אין לפרש זאת כסף של 0dBFS.

`defaultCycleSeconds` הוא משך המחזור ההתחלתי שנלמד בכיול. בחיבור החי,
העזיבה האמיתית הראשונה תקבע את עוגן הזמן; המרווח התקין הראשון בין שתי עזיבות
אמיתיות יחליף את ברירת המחדל במדידה חיה. ברירת המחדל אינה דגימת מחזור נוספת
למיצוע, ואין להשתמש בזמן עזיבה מהקלטה ישנה כעוגן חי.

הפרופיל המצומצם `band_level_snr_v1` מגדיר סינון לפי תחום תדרים, יחס אות לרעש,
עוצמת אירוע ומשך הצליל. יחידות העוצמה הן של כיול v2: PCM מנורמל, חלון Hann,
נרמול הספק לפי אנרגיית החלון ואחוזון 90 של חלונות האירוע. פרופיל זה מיועד
לגלאי החי המשולב; ניתוח הדמיון הספקטרלי המלא של תהליך הכיול נשאר בדוח המפורט.
השרת טוען קובץ זה כשמעבירים `--detector-config`, ומפעיל את הגלאי באמצעותו.

כאשר התוצאה היא `review` או `insufficient_evidence`, נשמר הדוח המלא בלבד.
קובץ הגדרות קיים נשמר ללא שינוי, והפקודה מציינת במפורש שלא עודכן ומחזירה 1.
שגיאת קלט או כתיבה מחזירה 2. כל קובץ נכתב תחילה לקובץ זמני ומוחלף לאחר
השלמת הכתיבה; הדוח המלא וקובץ ההרצה חייבים להיות בשני נתיבים שונים.

אפשר להעביר כמה קבצים או תיקיות באותה פקודה; `--recursive` כולל תתי־תיקיות.
קבצים זהים מזוהים לפי תוכן ואינם נספרים כחזרות נוספות. חפיפות בזמן או קבצים
שונים עם אותה חותמת זמן נדחים. הנתונים נקראים במקטעים, בלי לטעון את כל השמע לזיכרון.

הנחת הכיול היא **צליל חוזר בעת עזיבת קומה 7**, עם מחזור קבוע **גדול מ־300 וקטן
מ־1,800 שניות**. הכלי מחפש מאפייני תדר וזיהויים שחוזרים במחזור מתאים; הוא אינו
מניח מראש את התדר או את סף האנרגיה מהקוד הישן. התוצאה כוללת פרמטרים מוצעים,
זמני אירועים, ראיות למחזור וחלופות. ללא מספיק חזרות או במקרה של תוצאות מתחרות,
הדוח מציין את המגבלה. זהו כיול ללא תיוג ידני; ציוני ההתאמה אינם אחוזי דיוק מוכחים.

אותו צלצול נשמע לעיתים גם מקומות אחרות, בעוצמה נמוכה בהרבה. הכיול מתחשב לכן
גם **בעוצמת הצליל בתחום התדרים שנבחר**, לצד הדמיון האקוסטי והמחזוריות.
הוא מחפש הפרדה בין סדרת צלצולים חזקה וחוזרת לבין צלצולים דומים וחלשים.
יחס אות לרעש לבדו אינו מספיק: גם צלצול רחוק וחלש עשוי לבלוט כשהסביבה שקטה.
העוצמה נשמרת ביחס לטווח הדגימות המקורי; אין הגברה או נרמול של כל קובץ בנפרד.
לכיול ולשימוש בפרמטרים יש לשמור על אותו מיקרופון, מיקום והגבר קלט.
אם מופעלת הגברה אוטומטית (AGC) במיקרופון או במערכת, היא עשויה לצמצם את
הבדלי העוצמה שעליהם נשען הכיול; יש להשתמש בהגבר קבוע.
המקליט אינו משנה את הגדרות עיבוד השמע של מערכת ההפעלה.
[הסבר על פעולת AGC](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/audio-signal-processing-modes).

החיפוש הנוכחי מתאים לצליל בעל רכיבי תדר בולטים: הוא סורק 200–8,000 הרץ
(עד חצי קצב הדגימה), בוחן רוחבי פס וספי יחס אות לרעש, ומשווה את הספקטרום
ומשך הצליל בין חזרות. רעש מכני רחב־פס עשוי לדרוש גלאי אחר.
ב־WAV רב־ערוצי נבחר הערוץ הראשון; `--channel` מאפשר לבחור ערוץ אחר, החל מ־0.
`--timing-tolerance` מגדיר סטייה מותרת ממחזור קבוע, בשניות (ברירת מחדל 3),
ו־`--merge-gap` מאחד צפצופים סמוכים לאירוע (ברירת מחדל 1.5 שניות).

שדות מרכזיים בדוח JSON:

| שדה | משמעות |
|---|---|
| `status` | `ready`: נמצא מועמד שעומד בכללי החיפוש; `review`: נדרשת בדיקה; `insufficient_evidence`: לא נמצאו מספיק ראיות |
| `periodSeconds` | זמן המחזור המוצע, או `null` |
| `parameters` | תחום תדרים, סף יחס אות לרעש, סף עוצמת צלצול אם נמצא, משך אירוע וחתימה ספקטרלית |
| `intensitySeparation` | האם נמצאה הפרדה בין צלצולים חזקים לחלשים, פער העוצמה ומספר המועמדים החלשים שסוננו |
| `matchingEvents` | זמני האירועים, עוצמתם, קובצי המקור והמיקום בתוכם לצורך בדיקה |
| `support`, `alternatives` | מספר חזרות, שגיאת תזמון, התאמה בין צלילים ומועמדים מתחרים |

זמן אירוע הוא תחילת חלון השמע הראשון שהתאים, ולכן הוא אומדן לזמן הצליל.
גם `ready` מחייב אימות שהצליל שייך למעלית. קוד היציאה הוא 0 עבור `ready`,
1 עבור דוח הדורש בדיקה או עוד הקלטות, ו־2 עבור שגיאת קלט. הדוח נשמר גם כשאין
מספיק ראיות, ללא בחירה אוטומטית בזמן המחזור של הסימולציה.

`parameters.minimumEventBandDbfs` הוא סף מוצע לעוצמת אירוע שלם בתחום התדרים,
ולא לעוצמת דגימה בודדת. המדד הוא האחוזון ה־90 של הספק חלונות השמע הפעילים,
ביחידות dBFS (ביחס לטווח הדגימות הדיגיטלי). עוצמה נמדדת זו מופיעה גם ב־
`matchingEvents[].eventBandDbfs`; אין כאן מדידת דציבלים פיזיקלית מכוילת.
סף נלמד רק כשקיימת הפרדת עוצמות מספקת וסדרת צלצולים חזקים מחזורית.
ברירת המחדל דורשת פער של לפחות 6dB ולפחות שלושה צלצולים חזקים מתאימים;
צלצול חזק בודד אינו קובע את הסף.
כאשר אין הפרדה כזו, הסף הוא `null`; צלצולים מחזוריים מתחרים נשארים לבדיקה.

יש לספק קבצים בעלי שמות זמן כמו הקבצים המקוריים, כדי לשמור על פערי ההקלטה.
עדיף להקליט כמה שעות כשהמעלית במסלול שבת קבוע. נדרשות לפחות שלוש הופעות של
אותו צליל, ומומלץ לבדוק את הפרמטרים גם על הקלטה נפרדת מזו ששימשה לכיול.
הקלטות ותוצאות בתיקיית `data/` אינן עולות ל־Git.

**עזיבה והגעה הן נקודות זמן שונות.** תוצאת הכיול, הגלאי החי והאתר משתמשים
בעוגן `departure` בקומה 7. קצב המחזור לבדו אינו מודד את זמני העצירה בשאר הקומות.

ברזברי הקיים הגלאי והמקליט פועלים ב־Python 3.11 עם PortAudio ו־NumPy של
מערכת ההפעלה, לפי הוראות ההכנה בהמשך. הכיול המלא רץ במחשב הפיתוח על אותם
קובצי WAV, עם קבוצת התלויות `audio` הכוללת גם SciPy.

## הגלאי החי וממשק הנתונים

השרת מפעיל גלאי שמע רציף באותו תהליך שבו פועל ממשק הנתונים. הגלאי מסנן לפי
קובץ הכיול המצומצם, מעביר עזיבות מזוהות ישירות למצב המשותף ומשדר אות חיים
רק בעקבות קבלת מקטעי שמע טריים. אין צורך בתהליך נפרד ששולח בקשות HTTP.

לבדיקה מקומית עם מיקרופון, לאחר התקנת קבוצת `audio`:

```powershell
uv run --group audio python run_metrics_server.py --live --detector-config data/server-config.json --audio-device "USB PnP Sound Device" --monitor-only
```

- `--live`: נתונים אמיתיים או המתנה להם; ללא יצירת אירועים אוטומטית.
- `--detector-config`: נתיב ל־JSON המצומצם; מחייב `--live`.
- `--audio-device`: שם התקן PortAudio או מספרו. שם התקן עדיף, כי המספר עלול להשתנות.
  אפשר לקבל רשימה עם `run_record_audio.py --list-devices`.
- `--monitor-only`: בדיקת המיקרופון ורישום מועמדים ביומן, ללא דיווח עזיבות מהגלאי.
  מחייב קובץ כיול; השרת מחזיר `monitorOnly: true` והאתר מציג מצב בדיקה ללא תחזית.
- `--sample-rate`: קצב דגימה; ברירת המחדל היא 44,100.

בלי `--detector-config`, הפקודה `python run_metrics_server.py --live` מפעילה
ממשק נתונים בלבד, ללא גישה למיקרופון. קובץ הכיול אינו נטען אוטומטית מתיקיית
`data/`; יחידת השירות מעבירה את נתיבו במפורש. אפשר להגדיר גם
`DETECTOR_CONFIG` ו־`AUDIO_DEVICE` בסביבת התהליך או ב־`.env`.

### עוגן הזמן ומדידת המחזור

האירוע הוא **עזיבה של קומה 7**, המסומנת `anchorKind: "departure"` ו־
`lastDepartureAt`. האתר מתחיל את חישוב המסלול לאחר העצירה בקומה 7;
הוא אינו מפרש את אותו זמן כהגעה. `lastDetectionAt` מציין אותו זיהוי,
ו־`lastArrivalAt` נשאר `null` במקור המבוסס על עזיבה.

השרת טוען את `defaultCycleSeconds` מקובץ הכיול. לפני עזיבה אמיתית ראשונה
אין עוגן ואין תחזית. לאחריה מוצג המחזור ההתחלתי עם `cycleSource: "default"`.
המרווח התקין הראשון בין שתי עזיבות מחליף אותו בדיוק, עם
`cycleSource: "measured"`; ברירת המחדל אינה משתתפת במיצוע. בהמשך משתמשים
בחציון של עד חמש מדידות תקינות. מחזור חייב להיות **גדול מ־300 וקטן מ־1,800
שניות**, ללא הכללת הגבולות.

אירועים כפולים, אירועים מחוץ לסדר וזיהויים מוקדמים מדי אינם מאפסים את העוגן.
מרווח חריג ארוך בזמן חיבור רציף שומר על המחזור הקודם ומסמן אי־ודאות במקום
להכפיל את המחזור. המרווח נלמד רק בתוך רצף חיבור תקין, ולא על פני אתחול או
ניתוק. ללא מחזור מדוד קודם אי אפשר להוכיח משני צלילים בלבד שלא הוחמצה עזיבה;
לכן נדרש אימות ההקלטות בשטח.

### אות חיים, תקלות ומצב ציבורי

`GET /api/state` פתוח לקריאה ומחזיר את עוגן העזיבה, מקור המחזור, זמן אות החיים
האחרון, קישוריות ומצב `waiting`, `tracking`, `stale` או `uncertain`.
האתר מבקש את המצב מהשרת כל **30 שניות**, וגם מיד בטעינה, בחזרה ללשונית
ובחזרת החיבור לאינטרנט. הספירה לאחור על המסך מתעדכנת בכל שנייה.
הגלאי מדווח אות חיים בערך כל חמש שניות של שמע שהתקבל בהצלחה. עצם פעילות
שרת HTTP אינה הוכחה שהמיקרופון עובד. כשקליטת השמע נכשלת, הקישוריות מתבטלת
מיד והשרת מנסה לפתוח את המיקרופון מחדש; ממשק הקריאה נשאר פעיל.

אחרי 90 שניות ללא אות חיים טרי המקור נחשב מנותק. אות חיים שחזר מוכיח חיבור
בלבד: אחרי ניתוק או אתחול נדרשת **עזיבה חדשה** כדי להחזיר תחזית אמינה.
בתום המחזור החזוי, ללא זיהוי נוסף, התחזית מושהית. השרת והאתר אינם ממציאים
עזיבה חדשה על סמך טיימר ואינם עוברים אוטומטית להדגמה כשאין מדידות.

העוגן, מדידות המחזור ומזהי האירועים האחרונים נשמרים ב־`data/state.json`,
שאינו עולה ל־Git. היסטוריה זו נשמרת באתחול אך אינה מחזירה ביטחון בעוגן ישן.
זהו מצב אחרון מוגבל, לא יומן נסיעות מלא. הגלאי החי אינו שומר או משדר אודיו;
שמירת קובצי שמע מתבצעת רק בהפעלה מפורשת של כלי ההקלטה.

### ממשק קליטה מקומי למקור חיצוני

הממשק נשאר זמין אם מחברים בעתיד מקור חיצוני במקום הגלאי המשולב. הוא דורש
`INGEST_TOKEN` אקראי ב־`.env`, ואינו חשוף דרך המנהרה הציבורית:

```http
POST /api/observations
Authorization: Bearer <INGEST_TOKEN>
Content-Type: application/json
```

```json
{
  "deviceId": "begin17-floor7",
  "eventId": "unique-id-for-this-departure",
  "eventKind": "departure",
  "floor": 7,
  "observedAt": "2026-10-09T18:00:00+03:00"
}
```

`observedAt` חייב לכלול אזור זמן ולהיות טרי, עד 90 שניות. זמן עתידי ביותר
מחמש שניות נדחה. `eventKind` נדרש במפורש. שדה `cycleSeconds` ישן, אם נשלח,
נבדק אך אינו מאתחל מחזור מדוד; מקור ברירת המחדל הוא קובץ הכיול של השרת.

אות חיים נשלח לאותו ממשק מקומי, עם אותה הרשאת כתיבה:

```http
POST /api/heartbeat
Authorization: Bearer <INGEST_TOKEN>
Content-Type: application/json
```

```json
{"deviceId": "begin17-floor7", "observedAt": "2026-10-09T18:00:30+03:00"}
```

מקור חיצוני צריך לשלוח אותות חיים רק כל עוד מתקבל שמע טרי, ולשמור על שעון
מערכת מסונכרן. אין לשלוח אירועי בדיקה למצב האמיתי כדי לגרום לתחזית להופיע.

## חיבור דרך הדומיין בקלאודפלייר

כתובת שרת הנתונים היא `https://elevator-api.udidaniel.com`.
בחשבון קלאודפלייר אושרו הגישה ונוצרו מנהרה ורשומת DNS עבור כתובת זו.
האתר נשאר ב־GitHub Pages; הדומיין הראשי פנוי לשימושים אחרים.
תהליך `cloudflared` ברזברי יוצר את החיבור היוצא, ללא פתיחת פורטים בנתב
וללא צורך בכתובת אינטרנט קבועה.

השרת מאזין לכתיבה ולתצוגה מקומית ב־`127.0.0.1:8000`, ולקריאה ציבורית
ב־`127.0.0.1:8001`. שתי הכניסות משתפות מצב באותו תהליך Python.
המנהרה מופנית **רק ל־8001** וחושפת רק `GET /api/state` ו־`GET /api/health`.
כניסת הקריאה אינה מאפשרת כתיבה, גם עם אסימון תקין, ואינה מגישה קבצים.
התשובות הציבוריות כוללות `Cache-Control: no-store`.

### קובצי המנהרה ושירות ההפעלה

התצורה מבוססת על [deploy/cloudflared.yml.example](deploy/cloudflared.yml.example)
ונשמרת ברזברי ב־`/home/admin/shabat_elevator/secrets/cloudflared.yml`.
מזהה המנהרה ונתיב קובץ האישורים מופיעים רק בתצורה המקומית.
אישורי המנהרה נשמרים ב־`secrets/`, מחוץ ל־Git ול־`web/`, ובהרשאות פרטיות.
אין צורך להעתיק לרזברי את אישור ניהול החשבון שנוצר בעת `tunnel login`.

[יחידת השירות](deploy/cloudflared.service) מפעילה את המנהרה אוטומטית לאחר
אתחול ומנסה להתחבר מחדש לאחר כשל. בהתקנה חדשה, לאחר העברת התצורה
והאישורים המתאימים והתקנת `cloudflared`:

```bash
cd /home/admin/shabat_elevator
cloudflared --config secrets/cloudflared.yml tunnel ingress validate
sudo install -m 0644 deploy/cloudflared.service /etc/systemd/system/cloudflared.service
sudo systemctl daemon-reload
sudo systemctl enable --now cloudflared.service
sudo systemctl status cloudflared.service
```

אין ליצור מחדש את המנהרה או לדרוס את רשומת ה־DNS הקיימת בכל פריסה.
אין להפעיל במקביל מנהרת ניסוי במחשב הפיתוח עם אותו מזהה, מפני שבקשות עלולות
להגיע לשני שרתים בעלי מצב שונה. להקמת מנהרה חדשה בחשבון אחר ראו
[הוראות היצירה](https://developers.cloudflare.com/tunnel/features/locally-managed-tunnels/create-local-tunnel/)
ו־[תצורת הנתיבים](https://developers.cloudflare.com/tunnel/features/locally-managed-tunnels/configuration-file/).

### אימות החיבור והאתר

בודקים ש־`https://elevator-api.udidaniel.com/api/health` זמין וש־`/api/state`
מחזיר `mode: "live"`. במצב ההכנה צפוי `monitorOnly: true`; חיבור מיקרופון תקין
יכול להציג `sourceConnected: true` גם בלי עזיבה ובלי תחזית. בדיקת תקינות השרת
לבדה אינה מאשרת זיהוי מעלית.

בודקים ש־`/api/observations`, `/api/heartbeat`, `/config.json` ו־`/.env` אינם
זמינים דרך הדומיין. בשרת מגדירים `ALLOWED_ORIGIN=https://udid.github.io`,
וב־`web/config.json` מגדירים `sourceMode: "live"` ו־
`liveApiUrl: "https://elevator-api.udidaniel.com"`. אין אסימון גישה בקובצי האתר.
לאחר פרסום בודקים קריאה גם בטלפון דרך אינטרנט סלולרי.

הסקריפט מכין `.venv` של Python 3.11 עם `--system-site-packages`, כדי להשתמש
בחבילת NumPy ‏1.24 של Debian במכשיר הקיים. הוא מתקין `python3-numpy`
ו־`libportaudio2` אם חסרים, ואת `sounddevice==0.5.6` ותלויותיו מחבילות בינריות
ב־PyPI וב־piwheels. הגלאי אינו דורש SciPy; הכיול המלא מתבצע במחשב הפיתוח.
המסלול נפרד מסביבת Python 3.13 המוגדרת ב־`pyproject.toml` וב־`uv.lock`.
בהרצה חוזרת, כשכל התלויות קיימות, אפשר להוסיף `--skip-deps`.

נוצרים `data/` וקובץ `.env` בהרשאת `0600` עם אסימון אקראי, רק אם הקובץ אינו
קיים. קובץ קיים נשמר. הסקריפט מאמת את הכיול, מריץ בדיקות שרת, מקליט, גלאי
ומצב בלי לפתוח מיקרופון, ומתקין את [יחידת השירות](deploy/shabat-elevator.service)
לאחר הצלחתן. הוא אינו מפעיל שירות בעצמו:

```bash
sudo systemctl enable --now shabat-elevator.service
sudo systemctl status shabat-elevator.service
```

השירות מפעיל יחד את הגלאי ואת שרת הנתונים, ובוחר את המיקרופון בשם
`USB PnP Sound Device`. במכשיר אחר יש להתאים את שם ההתקן.
קובצי התוכנה לקריאה בלבד בתוך השירות; המצב נכתב ל־`data/`.
סקריפט ההכנה אינו משדרג מערכת, מאתחל אותה או משנה הגדרות SSH ו־cron.

### הפעלה אוטומטית ובדיקת שטח בקומה 7

הפריסה הפעילה מפעילה זיהוי ודיווח עזיבות בכל הפעלה של הרזברי, ללא
`--monitor-only`. גם מנהרת קלאודפלייר מוגדרת להפעלה אוטומטית. אפשר לבדוק זאת:

```bash
sudo systemctl is-enabled shabat-elevator.service cloudflared.service
sudo systemctl is-active shabat-elevator.service cloudflared.service
```

ב־`/api/state` מצפים ל־`monitorOnly: false`, ול־`sourceConnected: true` עם
`lastSeenAt` שמתעדכן כל עוד המיקרופון מספק שמע. חיבור תקין מעיד על פעילות
הגלאי, אך דיוק הזיהוי עדיין דורש אימות בשטח. לאחר אתחול ממתינים לזיהוי חדש
לפני חידוש התחזית, גם אם נשמרה היסטוריית זיהויים.

לאחר התקנת הרזברי והמיקרופון בקומה 7, באותו מיקום והגבר שישמשו לכיול,
משלימים הקלטות ובדיקת שטח ביום שישי כשהמעלית פועלת במסלול שבת.
ממתינים לעזיבה אמיתית ראשונה ולמחזור תקין נוסף, ומשווים את הזמנים למעלית
בפועל. הגלאי מאזין כל עוד השירות פועל; לוח השבת באתר קובע מתי מוצגת התחזית.
זמני הנסיעה והעצירה בין יתר הקומות עדיין משוערים ודורשים מדידה נפרדת.

`--monitor-only` נשאר זמין לבדיקה ידנית מפורשת: הוא מפעיל קליטת שמע ורושם
מועמדים ביומן, אך אינו מפרסם זיהויי עזיבה. הוא אינו מוגדר בפריסה הפעילה.
אם הוגדר בעבר מצב ההכנה באמצעות הקובץ המקומי
`/etc/systemd/system/shabat-elevator.service.d/preparation.conf`, מסירים רק אותו
כדי לחזור לזיהוי ודיווח רגילים:

```bash
sudo rm -- /etc/systemd/system/shabat-elevator.service.d/preparation.conf
sudo systemctl daemon-reload
sudo systemctl restart shabat-elevator.service
```

לאחר המעבר בודקים שוב ש־`monitorOnly` הוא `false` ושהמיקרופון מדווח.

### הקלטה ברזברי ותחזוקה

המקליט והגלאי משתמשים באותו מיקרופון USB. עוצרים את שירות הגלאי לפני הקלטה
נפרדת, ומשאירים את המנהרה פעילה כדי שהאתר יוכל לדווח שהחיישן אינו זמין:

```bash
cd /home/admin/shabat_elevator
sudo systemctl stop shabat-elevator.service
.venv/bin/python run_record_audio.py --list-devices
.venv/bin/python run_record_audio.py --device "USB PnP Sound Device" --output data/recordings/friday --duration-minutes 180
sudo systemctl start shabat-elevator.service
sudo systemctl status shabat-elevator.service
```

גם אם ההקלטה הופסקה או נכשלה, מפעילים מחדש את השירות לאחר סגירת המקליט.
בעת עצירת השירות כולו גם ממשק הנתונים אינו זמין; האתר משהה את התחזית
ומציג את מצב החיבור. ההפעלה מחדש מחזירה את הגלאי לזיהוי ולדיווח לפי הגדרות השירות.
אפשר להעביר את ההקלטות למחשב הפיתוח, להריץ כיול, להעתיק את קובץ ההרצה
החדש ל־`data/server-config.json` ואז להפעיל מחדש את השירות.

לבדיקת תקלות:

```bash
sudo journalctl -u shabat-elevator.service -n 100 --no-pager
sudo journalctl -u cloudflared.service -n 100 --no-pager
```

יש לבדוק כמה מחזורים מול תיעוד אמיתי: עזיבות שהוחמצו, זיהויי שווא וצלצולים
מקומות אחרות, לצד התאוששות מניתוק מיקרופון, רשת ואתחול. בדיקות סינתטיות
ושחזור הקלטות מול מועמדי הכיול בודקים את המימוש; מועמדים אלה אינם תיוג
ידני ואינם מוכיחים דיוק בשטח.


## בדיקות ופרסום

```powershell
uv sync --group audio
uv run --group audio python -m unittest discover -s tests -p "test_*.py" -v
node --test tests/*.test.mjs
```

בדיקות JavaScript דורשות Node 22 ומעלה, ללא התקנת חבילות npm. בדיקות השמע דורשות
את קבוצת `audio`; הן משתמשות בנתונים סינתטיים ואינן מפעילות מיקרופון.
בדיקת הדפדפן האופציונלית דורשת `uv sync --group dev`:

```powershell
python tests/browser_check.py
```

הבדיקה מצפה לשרת מקומי ב־8000 ול־Chrome מותקן; אפשר לשנות עם `BROWSER_PATH` ו־`TEST_URL`.
צילומי המסך נשמרים ב־`.artifacts/`, ואינם מתפרסמים עם הקוד.

GitHub Actions מריץ בדיקות בכל push ל־`master` ולאחר הצלחה מפרסם **רק את `web/`**
ל־GitHub Pages. אין סודות או קוד שרת בתוך חבילת האתר. ב־Settings → Pages יש לבחור
GitHub Actions כמקור הפרסום.
