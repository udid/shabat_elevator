# מעלית שבת — מנחם בגין 17, גבעת שמואל

אתר ציבורי בעברית למעלית אחת, עם בחירת קומה ללא ברירת מחדל, תחזית הגעה,
תצוגה לטלפון/טאבלט/מחשב, זמני שבת וחג, פרשת שבוע, מזג אוויר ובקשת השארת מסך דולק.

**הגרסה הנוכחית היא סימולציה מסומנת. אין עדיין זיהוי קולי או חיבור למעלית אמיתית.**

- אתר: <https://udid.github.io/shabat_elevator/>
- מאגר: <https://github.com/udid/shabat_elevator>

## הרצה מקומית

נדרש Python 3.13 ומעלה. לשרת עצמו אין תלויות חיצוניות.

```powershell
uv venv .venv
.\.venv\Scripts\python.exe main.py
```

פותחים <http://127.0.0.1:8000>. אפשר גם `python main.py` בכל מערכת עם Python מתאים.
אם נמצאים מחוץ לשעות שבת/חג, לוחצים **הפעלת הדגמה**. בחירת הקומה הראשונה תמיד ריקה;
לאחר בחירה היא נשמרת במכשיר לפי מזהה הבניין. כדי להסיר אותה בוחרים שוב באפשרות הריקה.

## התנהגות שסוכמה

- קומות: ‎-1, 0–12. קומה ‎-1 היא קומת חניון, ואינה קוד שגיאה או כיוון.
- מקור המדידה העתידי: Raspberry Pi עם מיקרופון בקומה 7, שמזהה **עצירה** בקומה זו.
- מיקום וכיוון מחושבים הם הערכות; אירוע החיישן מתייחס רק לקומה 7.
- מחזור הדגמה מלא: **570 שניות (09:30)**, מהגעה לקומה 7 עד ההגעה הבאה אליה.
- המסלול המעגלי, בדיוק בסדר שנמסר:

```text
0, 0, 12, 10, 8, 6, 4, 2, -1, 0, 11, 9, 7, 5, 3, 1, -1 → חזרה להתחלה
```

שתי הופעות 0 הרצופות בתחילת הרשימה הן עצירה אחת בעלת משך כפול.
הביקור האחר ב־0 נשמר לפי הרשימה כעצירה רגילה. אין נסיעה פיקטיבית בין שני אפסים.
בקומות שמופיעות יותר מפעם במחזור, מחושב הזמן לביקור הקרוב ביותר.

זמני הביניים הם **הנחות הדגמה**: יחס של 3 שניות לכל קומה בנסיעה ו־12 שניות לכל יחידת
עצירה, ולאחר מכן התאמה יחסית של הכול ל־570 שניות. אלו אינם זמנים שנמדדו בבניין.
ההגדרות נמצאות ב־[web/config.json](web/config.json). אפשר לשנות את היחסים, המסלול,
`stopWeights` לפי קומה ואת משך המחזור. יש לכייל את מודל הנסיעה לפני שימוש בתחזית אמיתית.

## לוח פעילות

חלון הפעילות מתחיל **60 דקות לפני כניסת שבת או חג ומסתיים 60 דקות אחרי צאתם**.
אירועי חג/שבת רצופים מחוברים לחלון רציף. חול המועד לבדו אינו מפעיל מצב שבת.
הזמנים מחושבים ב־`Asia/Jerusalem`, לרבות שעון קיץ, עבור אזור גבעת שמואל
בקואורדינטות `32.078, 34.847`.

מקור הזמנים הוא Hebcal עם לוח ישראל: הדלקת נרות 18 דקות לפני השקיעה ויציאה לפי
צאת הכוכבים בשיטת 8.5 מעלות (`M=on`). `havdalahMinutes: null` בוחר שיטה זו;
מספר מפורש מחליף אותה בדקות לאחר השקיעה, לפי ההגדרה המקומית הרצויה.
אלו הגדרות לוח האתר; יש להתאים אותן גם לשעון הבקרה בפועל של המעלית.

אם לוח השנה אינו זמין ואין עותק תקף בזיכרון, האתר מסמן שחלון הפעילות אינו ידוע.
אפשר להפעיל הדגמה יזומה גם בימי חול. היא תמיד מסומנת ואינה משנה את לוח השבת.
מזג האוויר מתעדכן בנפרד; כשל בו אינו מפסיק את חישוב המעלית.

השארת המסך דולק משתמשת ב־Screen Wake Lock ב־HTTPS או localhost. נדרש אתר גלוי
ודפדפן תומך; מערכת ההפעלה יכולה לשחרר את הנעילה. האתר מציג את מצב הנעילה ומנסה
לחדש אותה בחזרה ללשונית. מצב מסך מלא זמין בנפרד.

## חיבור הרזברי בשלב הבא

שרת Python מספק כבר ממשק לדיווח אירועים. קוד הקלט מהמיקרופון, זיהוי הצליל,
הכיול האקוסטי והפעלת השירות על הרזברי **טרם מומשו**, בהתאם להפרדה לשלב הבא.
האתר ב־GitHub Pages מגיש קבצים בלבד. לקבלת מדידות אמיתיות יש להפעיל גם את שרת
הנתונים מאחורי HTTPS, או מתאם תואם, ולהגדיר את כתובתו באתר.

1. מעתיקים `.env.example` ל־`.env` ובוחרים `INGEST_TOKEN` אקראי ארוך.
2. מפעילים `python main.py --live`. האתר המקומי ממתין לנתונים אמיתיים.
3. הרזברי שולח אירוע לכל עצירה מזוהה בקומה 7 ו־heartbeat מדי כ־30 שניות.
4. לאתר Pages מגדירים `sourceMode: "live"` ו־`liveApiUrl` לכתובת שרת HTTPS.
   בשרת מגדירים `ALLOWED_ORIGIN=https://udid.github.io`.

צפייה אינה דורשת סיסמה. רק דיווח מהמכשיר דורש אסימון, שאסור לשים בקוד הדפדפן.

### אירוע עצירה

```http
POST /api/observations
Authorization: Bearer <INGEST_TOKEN>
Content-Type: application/json
```

```json
{
  "deviceId": "begin17-floor7",
  "eventId": "unique-id-for-this-stop",
  "floor": 7,
  "observedAt": "2026-10-09T18:00:00+03:00",
  "cycleSeconds": 570
}
```

`observedAt` הוא זמן הזיהוי במכשיר, עם אזור זמן. `cycleSeconds` אופציונלי: מאפשר
לרזברי שכבר צבר היסטוריה למסור מחזור התחלתי שנמדד. אחרת נדרשות שתי הגעות תקינות.
אחרי כן השרת לומד מהמרווחים בין האירועים, ומשתמש בחציון של עד חמש מדידות תקינות.
הטווח המתקבל הוא 120–3600 שניות; יש להתאימו בעת הכיול אם נדרש.

אירועים כפולים, ישנים מחוץ לסדר או מוקדמים באופן בלתי סביר אינם מאפסים את העוגן.
מרווח ארוך חריג עשוי לציין זיהוי חסר: הוא מעדכן את ההגעה האחרונה אך אינו מכפיל
אוטומטית את משך המחזור. ללא מחזור קודם אין אפשרות להוכיח ששני זיהויים היו רצופים;
איכות הזיהוי והכיול נשארת באחריות שלב המדידה.

### אות חיים ומצב ציבורי

```http
POST /api/heartbeat
Authorization: Bearer <INGEST_TOKEN>
Content-Type: application/json
```

```json
{"deviceId": "begin17-floor7", "observedAt": "2026-10-09T18:00:30+03:00"}
```

`GET /api/state` פתוח לקריאה ומחזיר זמן הגעה, מחזור נלמד, זמן אות החיים האחרון,
קישוריות ומצב `waiting`, `tracking`, `stale` או `uncertain`. אות חיים אינו נחשב להגעה.
אחרי 90 שניות ללא אות חיים המקור נחשב מנותק. בתום המחזור החזוי ללא זיהוי חדש
התחזית מושהית; השרת לעולם אינו ממציא הגעה חדשה על סמך טיימר.

העוגן, מדידות המחזור ומזהי האירועים האחרונים נשמרים ב־`data/state.json`, שאינו עולה
ל־Git. בהפעלה מחדש ההיסטוריה נשמרת, אך נדרש אות חיים חדש להוכחת חיבור.
קובץ זה הוא מצב אחרון מוגבל, לא היסטוריית נסיעות מלאה. אודיו אינו נשמר או משודר.

## בדיקות ופרסום

```powershell
python -m unittest discover -s tests -p "test_*.py" -v
node --test tests/*.test.mjs
```

בדיקות JavaScript דורשות Node 22 ומעלה, ללא התקנת חבילות npm. בדיקות Python
משתמשות בספרייה הסטנדרטית. בדיקת הדפדפן האופציונלית דורשת `uv sync --group dev`:

```powershell
python tests/browser_check.py
```

הבדיקה מצפה לשרת מקומי ב־8000 ול־Chrome מותקן; אפשר לשנות עם `BROWSER_PATH` ו־`TEST_URL`.
צילומי המסך נשמרים ב־`.artifacts/`, ואינם מתפרסמים עם הקוד.

GitHub Actions מריץ בדיקות בכל push ל־`master` ולאחר הצלחה מפרסם **רק את `web/`**
ל־GitHub Pages. אין סודות או קוד שרת בתוך חבילת האתר. ב־Settings → Pages יש לבחור
GitHub Actions כמקור הפרסום.
